# NUBO｜台中一中館現場 AI 查房／訂房引導 V1（測試中）

## 目標
現場旅客快速知道指定日期或時段是否有可售房；希望訂房時引導至櫃檯或已驗證可用的線上訂房頁。只查 PMS 可售房型與數量，不讀已售房間、住客個資、付款等資料。

## 既有接口（唯讀）
- 館別：ainubo-taichung-jinxin
- NUBO 主畫面查住宿：POST /api/pms/v1/availability
- NUBO 主畫面查休息：POST /api/pms/v1/rest-availability
- nubosci 語音合作端：POST /api/partners/nubosci/v1/availability、/rest-availability
- 既有 PMS 端：/api/voice/v1/availability 及 /rest-availability（環境變數存取，不公開 Token）

## 現場問答
1. 住宿先取得入住日、退房日或晚數、每間成人數，立刻查 PMS；休息則先取得開始時間與時長，再查專用休息接口。
2. 只有完整、未過期、相符的 guest-room-types-v1 房型明細與有效非負整數 availableCount 才可回答；先說有無，推薦最多一種適合房型。
3. 客人明確問有幾間時，才可播報本次查得的指定房型 availableCount，不把不同房型混加；沒有房型清單、只有總量或查詢失敗都不得當成客滿。
4. 指定房型已確認零間時，先說該房型此時段沒房，再只建議一種同次查到、條件相符的替代房型。客人拒絕後不重薦。
5. 客人明確願意訂房／入住時，主 NUBO 呼叫既有 notify_arrival_intent；只有 sent=true 或 duplicate=true 才能說通知成功。若 LINE 失敗或額度滿，請客人直接洽櫃檯。
6. nubosci 合作語音只有唯讀查詢工具，直接引導櫃檯；不能假裝已通知。只有經訂房連結 API 確認可下單，才能引導點選訂房頁。
7. 可售房不等於保留，查房後至實際下單前必須由 PMS 再確認庫存和正式價格。NUBO 不建立訂單、不收款、不派房。

## 失敗模式與驗收
- PMS 回 503、資料過期或房型資料不完整：只能說目前無法確認，請洽櫃檯。
- LINE 通知 429 或錯誤：不能說已成功通知。
- 庫存瞬間變動：只代表查詢當下，不保證訂房成功。
- 自動化測試：來源驗證、已確認零與未知、住宿／休息分流、語音提示、明確問可售間數、交接與通知失敗防護。
- **正式驗收尚未完成**：必須在櫃檯實機以當下 PMS 真實房型與數量確認語音回答，並檢查通知／訂房轉介；未通過不得合併或部署正式環境。

本修正不改正式 PMS 寫入 API、付款或任何住客資料。
