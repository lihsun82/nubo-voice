# NUBO OmniRoute Cloud — Render Singapore

目標：Windows 關機時，手機 NUBO 仍可透過雲端 OmniRoute 使用 AI fallback / Agent。

## 架構

```text
手機 NUBO
  -> nubo.ainubo.com
  -> NUBO Backend
  -> https://<render-service>.onrender.com/v1
  -> OmniRoute auto
  -> free / paid providers with fallback
```

## 為什麼不用 Render Free

Render Free Web Service 會在閒置後休眠，下一次請求需要 cold start。NUBO 的目標是手機隨時可用，因此正式建議使用 Starter 常駐服務。

## Blueprint

使用：

```text
deploy/render.omniroute.yaml
```

主要設定：

- Region: Singapore
- Runtime: prebuilt Docker image
- Image: `diegosouzapw/omniroute:3.8.48`
- Service plan: Starter
- Persistent disk: 1 GB mounted at `/app/data`
- `REQUIRE_API_KEY=true`
- SQLite / provider credentials persist on disk
- secrets are generated by Render or entered manually

## 第一次部署

1. 登入 Render。
2. 建立 Blueprint。
3. 連接 `lihsun82/nubo-voice` repo。
4. Blueprint path 指定：

```text
deploy/render.omniroute.yaml
```

5. Render 會要求輸入 `INITIAL_PASSWORD`。請使用全新、只給 OmniRoute dashboard 用的強密碼，不要使用 Gmail / GitHub / LINE 密碼。
6. 建立服務。
7. 等 health check `/api/monitoring/health` 成功。

## 第一次登入與 API Key

部署後開啟：

```text
https://<render-service>.onrender.com/dashboard
```

使用 `INITIAL_PASSWORD` 登入。

在 OmniRoute Dashboard 建立一把只給 NUBO 使用的 API Key。不要把 Dashboard 密碼當 API Key 使用。

建議名稱：

```text
nubo-mobile-cloud
```

## NUBO 雲端環境變數

把 NUBO Backend 的環境變數改為：

```env
NUBO_OMNIROUTE_ENABLED=1
OMNIROUTE_BASE_URL=https://<render-service>.onrender.com/v1
OMNIROUTE_API_KEY=<OmniRoute dashboard 建立的 NUBO 專用 API key>
OMNIROUTE_MODEL=auto
```

注意：不要再使用：

```env
OMNIROUTE_BASE_URL=http://127.0.0.1:20128/v1
```

否則仍會依賴 Windows。

## Provider 策略

先使用 OmniRoute `auto`。最低成本建議：

1. free / free-forever provider
2. Groq / NVIDIA / Cerebras 等有免費層 provider
3. Gemini / Grok / OpenAI 只作必要 fallback

不要一次把所有 OAuth / API Key 全塞進去；先用 2–3 個低風險 provider 驗證。

## 驗收

### A. OmniRoute health

```text
GET https://<render-service>.onrender.com/api/monitoring/health
```

應回成功。

### B. Models

```text
GET https://<render-service>.onrender.com/v1/models
Authorization: Bearer <NUBO_API_KEY>
```

應回模型清單。

### C. Chat

使用 `model: auto` 呼叫 `/v1/chat/completions`，確認能回覆。

### D. NUBO fallback

1. `NUBO_OMNIROUTE_ENABLED=1`
2. 手機開 NUBO
3. 讓 Gemini quota error 或暫時停用 Gemini
4. NUBO 應顯示切換 OmniRoute
5. 手機可繼續文字/語音 fallback

### E. 最終斷電測試

1. Windows 完全關機
2. 手機關 Wi-Fi，只留 5G
3. 開啟 `nubo.ainubo.com`
4. 呼叫 NUBO
5. 執行一個 Agent/研究問答

只有這個測試通過，才算完成「手機獨立」。

## 安全邊界

- `REQUIRE_API_KEY=true`
- NUBO 使用獨立 API key
- 不把 OmniRoute Dashboard 密碼寫入 GitHub
- 不把 provider secrets 寫入 GitHub
- `/app/data` 使用持久磁碟
- `STORAGE_ENCRYPTION_KEY` 由 Render 產生並保存
- 不修改 LINE webhook / LINE 指令解析 / LINE 桌機控制穩定版

## 後續

OmniRoute 雲端 URL 與 NUBO API Key 確定後，將 `OMNIROUTE_BASE_URL` / `OMNIROUTE_API_KEY` 寫入 NUBO 實際雲端部署平台，再進行手機 5G + Windows 關機測試。
